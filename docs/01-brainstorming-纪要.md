## 4. 方案对比

### 4.1 前端架构

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯静态多页 HTML + Tailwind | 简单、零构建 | 10 个模块和状态流转难维护，无法接后端 | 否 |
| React SPA + 自建 JSON Mock | 开发快、原型稳定 | 无法真实写入数据库，不符合“可操作”要求 | 否 |
| React SPA + Go/Gin API（选用） | 真实 CRUD、状态流转、单二进制部署 | 需要同时维护前后端 | 是 |

### 4.2 车辆内容

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 只做数据表格 | 简单 | 不符合“车型展厅”与大幅摄影要求 | 否 |
| 每款车电商式详情页 | 内容丰富 | 超出 B 端运营范围 | 否 |
| 运营台 + 车型展厅 + 3D 车身（选用） | 兼顾运营效率与车型内容展示 | 资产与页面量增加 | 是 |

### 4.3 3D 实现

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 每款车精确 GLB | 最理想 | 免费资源不存在，采购成本高 | 否 |
| 360° 图片序列 | 每款车都能做 | 每款需 24-36 张，抓取与存储成本高 | 否 |
| 通用车身 GLB + 实拍（选用） | 真实 3D、可交互、资产可控、许可清晰 | 车身不是具体车型 | 是 |

## 5. 设计读数与参数

**Design Read**

> 内容驱动的网约车租赁运营台，实拍车辆与 3D 车身作为视觉主角，运营数据以不同尺寸卡片、进度条和图表嵌入，整体保持统一的间距、圆角和字体层级。

**三档参数**

| 参数 | 值 | 理由 |
|---|---|---|
| `DESIGN_VARIANCE` | 6 | 后台需要可预测，但总览用 7/5、4/4/4、8/4 非对称网格，避免模板感 |
| `MOTION_INTENSITY` | 5 | 主题扩散、抽屉、状态反馈、图表入场，全部有动机 |
| `VISUAL_DENSITY` | 6 | 运营表格保持紧凑，但给大幅摄影留呼吸空间 |

**taste-skill 边界**

该技能明确把 dashboard、数据表格、管理后台排除在适用范围外。因此不套用 landing page 的 hero、bento、图片规则，只吸收：

- 反模板纪律
- 单一强调色
- 形状锁
- 字体纪律
- 真实三态
- 动效必须有动机
- WCAG AA
- Pre-flight 检查

运营表格密度按 B 端后台最佳实践执行。

## 6. 最终设计摘要

### 6.1 产品

- 品牌：驰驿 CHEYI
- 定位：网约车租赁运营台
- 用户：运营主管、调度专员、财务专员
- 核心闭环：车型展厅 → 新建租约 → 签约 → 交车 → 月租账单 → 退租结算
- 10 个业务模块 + 登录 + 素材许可 + 404

### 6.2 技术

- 前端：React 19 + Vite 8 + TypeScript + Tailwind v4 + React Router 7 + TanStack Query 5
- 后端：Go + Gin + GORM + SQLite
- 认证：JWT HttpOnly Cookie + bcrypt，手机号登录/注册
- 开发：Vite 5173 + Gin 8090，Vite 代理 `/api`
- 生产：前端 dist 嵌入 Go 二进制，单端口
- 数据：首次启动自动建表并写入种子数据，`make reset-db` 重置

### 6.3 内容

- 16 款主流网约车车型，覆盖轿车、SUV、MPV、两厢、旅行车
- 实拍图来自 Wikimedia Commons，场景图来自 Unsplash
- 5 种通用车身 3D：轿车、SUV、MPV、两厢、旅行车
- 3D 支持旋转、缩放、颜色切换、自动旋转、重置、全屏
- 页面明确标注 3D 为车身示意，不是具体车型 CAD

### 6.4 视觉

- 亮色：暖白画布 + 白色卡片 + 安全橙强调
- 暗色：墨蓝黑画布 + 深色卡片 + 亮橙强调
- 字体：Geist + Geist Mono，中文回退 PingFang SC / Noto Sans SC
- 圆角：surface 12px、控件 8px、状态标签全圆角
- 主题切换：View Transitions 圆形扩散，700ms，固定从左下角展开
- 布局与组件结构在切换时完全不变，只过渡颜色、边框、状态

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 图片抓取不稳定 | 部分车型没图 | 多源回退：Wikimedia → 官方图 → 品牌占位卡；最多允许 2 款占位 |
| 图片版权 | 商用风险 | 免费授权优先；官方图标注来源与“仅展示”；`/credits` 与 `ASSETS.md` 明示 |
| 3D 资产不是实车 | 用户误解 | 页面标注“通用车身示意，非实车 CAD”；实拍图为主 |
| 4.8MB GLB 过大 | 首屏慢 | 只在 3D 标签激活时懒加载；压缩；离开视口暂停；WebGL 失败回退 poster |
| 10 个模块 + 后端范围大 | 交付压力 | 先文档与资产，再后端与壳层，再 Dashboard/展厅，最后运营模块 |
| View Transitions 兼容性 | 部分浏览器无动画 | 特性检测，降级为 180ms 淡入；reduced motion 立即切换 |
| SQLite 并发 | 多用户写入受限 | 单机部署足够；后续可换 Postgres |
| 单角色展示 | 无真实分权 | 注册账号与预置管理员均可登录；设置页展示角色但不做权限校验 |
