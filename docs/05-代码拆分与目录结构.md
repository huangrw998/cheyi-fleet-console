# 05 · 代码拆分与目录结构

> 日期：2026-11-25
> 范围：前端、后端、数据种子、类型、公共组件、业务逻辑
> 原则：先拆职责，再拆文件；拆分后路由、API、页面行为保持不变

---

## 1. 拆分原则

| 原则 | 落地方式 |
|---|---|
| 超过 200 行的页面必须拆分子组件 | 所有页面文件降到 150 行以内，页面只保留布局与组合 |
| 重复出现 2 次以上的 UI 模式抽取公共组件 | `StatStrip`、`StatusBadge`、`FilterBar`、`ModelCard`、`DataTable`、`Modal`、`PageHeader` 等 |
| 业务逻辑抽取到 hooks | 每个页面一个 `useXxx`，负责查询、参数、派生数据、mutation |
| 类型定义抽取到 types/ | `src/types/` 按领域拆成 13 个文件，统一由 `index.ts` 导出 |
| 前后端一致执行 | 后端 handler 按用例拆分，seed 按数据域拆分，models 按领域拆分 |

拆分后没有改变任何 URL、API 路径、请求字段、响应结构或页面交互。

### 后端业务逻辑归属

- `handler/dashboard.go`：只负责 HTTP 绑定与响应。
- `handler/dashboard_insights.go`：看板派生数据（最近租约、热门车型、门店统计）。
- `handler/dashboard_alerts.go`：风险提醒聚合与排序。
- `handler/dashboard_helpers.go`：状态标签与编号工具。
- `handler/leases_create.go`：创建租约事务。
- `handler/leases_actions.go`：签约、交车、退租、取消与状态机。
- `handler/leases_query.go`：列表与详情查询。
- `database/seed_*.go`：按数据域拆分种子数据，`seed.go` 只负责事务编排。

当前项目规模不额外引入 service 层，避免为拆分而拆分。如果后续继续增长，下一步可把 `leases_create.go`、`leases_actions.go`、`dashboard_insights.go` 中的领域事务迁移到 `internal/service`。

## 7. 类型目录

`src/types/` 按领域拆分，`index.ts` 统一导出：

- `common.ts`：金额、分页、错误
- `auth.ts`：用户
- `store.ts`：门店
- `vehicle.ts`：车型、车辆、车辆状态
- `driver.ts`：司机
- `lease.ts`：租约、事件、动作
- `billing.ts`：账单
- `operations.ts`：维保、保险、违章、调拨
- `analytics.ts`：总览、报表
- `settings.ts`：价格方案、设置
- `search.ts`：全局搜索
- `details.ts`：车型/车辆/司机详情组合
- `charts.ts`：图表数据点
- `requests.ts`：列表查询与表单写入请求类型
- `credits.ts`：素材许可结构

所有页面与 hooks 从 `@/types` 导入，不再从 `lib/types` 导入。
