# 10 · 前后端拆分方案与文件结构

> 日期：2026-11-26
> 范围：前端页面、组件、hooks、类型；后端 handler、models、seed、数据库
> 约束：拆分后 URL、API、请求字段、响应结构、页面功能保持不变

---

## 1. 拆分原则

| 原则 | 前端落地 | 后端落地 |
|---|---|---|
| 页面/文件超过 200 行必须拆分 | 页面只保留布局与组合；表单、表格、详情卡片、工具栏拆子组件 | handler 按用例拆分；detail/create/action/query 分开 |
| 重复出现 2 次以上的 UI 模式抽公共组件 | `Card`、`PageHeader`、`CardToolbar`、`Tabs`、`Button`、`DataTable`、`Modal`、`Input`、`Select`、`RichTextToolbar` 等 | 通用 `fail/ok/paginated/parseUintParam`、日期和查询 helper |
| 业务逻辑抽 hooks / composables | `pages/**/useXxx.ts` 负责查询、参数、派生数据、mutation | 事务/状态机放到独立 handler 文件或领域 helper；不在 HTTP 绑定里堆叠 |
| 类型定义放 types/ | `src/types/` 按领域拆分，`requests.ts` 放请求类型 | Go request struct 与 domain model 分离；前端不再使用宽泛 Record |

## 3. 请求与类型边界

- 前端请求只经过 `api/*.ts`；`api` 再调用 `lib/api.ts`。
- 请求参数和表单写入类型统一在 `types/requests.ts`。
- 页面与弹窗回调使用明确输入类型，不使用 `any` 或 `Record<string, unknown>`。
- 后端请求 struct 放在对应 handler 文件，领域模型放在 `internal/models/`，不互相污染。
