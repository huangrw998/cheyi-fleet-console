## 1. 产品概述

### 1.1 一句话定位

给网约车租赁公司用的车队与租约运营台，把“车租给司机跑网约车”这件事管清楚。

### 1.2 业务背景

网约车租赁公司的日常不是简单的“把车租出去”，而是同时管理：

- 车辆资产：车型、车牌、门店、里程、保险、年检、维保
- 司机：认证、证件、租约、租金、违章、退租
- 租约：签约、交车、在租、退租、结算
- 财务：月租、押金、违章代缴、车损、逾期
- 调度：门店库存、跨店调拨、运力平衡
- 风险：保险到期、保养到期、租金逾期、租约到期

驰驿把这些动作收进一个 B 端工作台，并用车型展厅与 3D 车身让“车”本身成为视觉主角。

### 1.3 产品原则

1. 先看车，再看数：大幅摄影与车型卡片承担视觉中心，运营数据在第二层。
2. 状态必须真实：每个按钮要么写库，要么明确禁用，不做假交互。
3. 风险前置：保险、租金、维保、租约到期在总览和通知里提前暴露。
4. 一套 Token：亮暗主题只换颜色、边框和状态，不换布局和组件结构。
5. 说明要清晰：3D 是通用车身，车型参数以车辆登记信息为准，素材许可见 `/credits`。

## 2. 目标与非目标

### 2.1 目标

- 10 个业务模块全部可访问、可操作
- 租约从创建到退租的完整状态流转
- 车辆、司机、维保、调度、账单、违章的真实 CRUD
- 16 款车型的实拍图与 5 种车身 3D
- 亮暗双主题与圆形扩散切换
- 桌面、平板、手机可用
- 生产环境单二进制启动

### 2.2 非目标

- C 端预订、支付、地图、GPS、电子合同、短信、发票、文件上传
- 多租户、真实 RBAC、审批流、批量导入、合同打印
- 精确的车型 CAD 与真实商业素材

## 3. 用户画像与用户故事

### 3.1 画像

| 角色 | 关注点 | 典型动作 |
|---|---|---|
| 运营主管 | 出租率、收入、风险、车型结构 | 看总览、看报表、处理逾期、决定调拨 |
| 调度专员 | 门店库存、待租车辆、交接 | 发起调拨、完成调拨、交车、退租 |
| 财务专员 | 应收、已收、逾期、押金、违章 | 登记收款、生成月租、处理违章、导出 CSV |
| 系统管理员 | 门店、价格、账号、提醒 | 修改门店容量、维护价格方案、改密码 |

首版不做真实角色分权；预置管理员和手机号注册的运营账号均可登录，角色只在界面展示。

### 3.2 用户故事

1. 作为运营主管，我想在总览一屏看到在租、待租、维保、逾期和本月应收，以便判断今天先处理什么。
2. 作为运营主管，我想看到本周主力车型和热门车型，以便决定采购与调拨。
3. 作为调度，我想按门店和状态查看车辆库存，以便把车调到更需要的门店。
4. 作为调度，我想三步创建租约，系统自动锁车并生成首期账单。
5. 作为调度，我想在租约详情完成签约、交车和退租，并记录里程与扣款。
6. 作为财务，我想筛选待收和逾期账单，登记收款并导出 CSV。
7. 作为财务，我想处理违章并自动生成待收账单。
8. 作为运营，我想看到保险 30 天内到期、保养待处理、租约即将到期的提醒。
9. 作为运营，我想在车型展厅比较 16 款车的续航、座位、月租和出租率。
10. 作为运营，我想在车型详情旋转 3D 车身、切换颜色，并查看在库车辆。
11. 作为管理员，我想修改门店容量、价格方案和提醒规则。
12. 作为用户，我想在亮色和暗色之间切换，并保持布局不变。

## 5. 功能规格

### 5.1 登录与会话

- 中国大陆手机号 + 密码登录
- 支持手机号注册；注册时按号段校验中国大陆运营商
- JWT 存 HttpOnly Cookie，8 小时有效
- 登录失败返回统一错误，不区分手机号不存在或密码错误
- 仅接受可识别号段的中国大陆手机号
- 未登录访问运营台重定向到 `/login`，登录后回到原页面
- 退出登录清 Cookie 与前端缓存
- 管理员账号：`123 8888 8888` / `Cheyi@2026`
- 登录页展示企业概览：车辆、司机、活跃租约数量

### 5.2 运营总览

**目标**：一屏看清车队、租约、风险和本周主力车型。

**内容**

- 大幅主视觉：本周主力车型，实拍图、品牌、车型、在租/在营、出租率、月租、进入车型详情、以此车型建租约（无空车时改为查看其他车型）
- KPI 条：在租车辆、待租车辆、维保中、逾期账单、本月应收、车队出租率
- 营收与出租率趋势：7/14/30 天切换，面积图 + 出租率虚线
- 车型资产组合：按车身类型的环形图与占比
- 今日交接：交车/还车时间线
- 风险提醒：保险、维保、租金、租约、违章
- 门店运力：门店图片、在租/容量、利用率
- 热门车型：3 张车型卡，图片、续航、在租/在营、月租、出租率
- 最近租约：司机、车牌、租约号、状态、月租

**规则**

- 所有数值来自数据库实时计算
- 无数据时展示空状态，不展示假数字
- KPI 条用 1px 分隔，不做 6 张独立卡片

### 5.3 车型展厅

- 16 款在营车型
- 搜索：品牌、车型名
- 筛选：车身类型、品牌
- 排序：推荐、月租升/降、续航、出租率
- 本周推荐：按可租数量与出租率排序的前 3 款
- 车型卡：实拍图、品牌、车型、车身类型、续航、座位、3D 标记、月租、押金、在租/在营、出租率进度、可租状态
- 筛选写入 URL search params
- 加载骨架、空状态、错误重试

### 5.4 车型详情

- 媒体区：实拍图标签、3D 看车标签
- 实拍：大图 + 缩略图切换
- 3D：通用车身 GLB，旋转、缩放、颜色切换、自动旋转、重置、全屏、加载进度、WebGL 失败回退
- 右侧：品牌、车型、车身类型、能源类型、可租状态、月租、押金、市场指导价、出租率、在租/在营
- 主操作：以此车型创建租约（无空车时禁用并引导查看其他车型）、查看在库车辆
- 核心参数：续航、电池、快充、座位、尺寸、轴距、能源、上市年份
- 车型亮点、在库车辆表格、相关车型
- 3D 免责声明

### 5.5 车辆资产

- 列表：搜索车牌/VIN、状态筛选、门店筛选、分页
- 统计：总车辆、在租、待租、维保中
- 表格：车牌/车型、门店、状态、月租、里程、保险到期、操作
- 排序：待租优先，其次已锁定、在租、维保、调拨
- 新增车辆：车牌、车型、门店、颜色、状态、里程、保险/年检到期、VIN
- 车辆详情：头图、状态、编辑档案、发起调拨、当前里程、保险到期、当前月租、当前租约
- 详情标签：车辆档案、租约记录、维保记录、保险与违章
- 编辑：状态、里程、保险到期、备注

### 5.6 租约订单

- 状态标签：全部、待签约、待交车、租用中、逾期、已退租、已取消
- 搜索：租约号、司机、车牌
- 门店筛选、分页
- 统计：生效中、待签约、待交车、在租月租
- 新建租约三步：
  1. 选择司机：只显示已认证且无生效租约的司机
  2. 选择车辆：只显示待租车辆，可按车型筛选
  3. 确认费用：起租日、租期 3/6/12 个月、到期日自动计算、月租、押金、备注
- 创建：事务内校验司机/车辆、锁车、生成首期租金账单、写租约事件
- 详情：状态、到期提醒、月租、押金、司机、车辆、租约进度、取/还车里程、账单记录、操作时间线
- 操作：
  - 待签约 → 签约 → 待交车
  - 待交车 → 交车（记录取车里程）→ 租用中
  - 租用中 → 办理退租（记录还车里程、扣款）→ 已退租
  - 待签约/待交车 → 取消 → 已取消
- 退租时扣款会生成一张待收车损账单

### 5.7 司机管理

- 列表：搜索姓名/手机号/驾照号、状态筛选、分页
- 统计：司机总数、已认证、租用中、待审核
- 表格：司机、状态、当前车辆、当前租约、评分、驾照到期、操作
- 新增司机：姓名、手机号、身份证号、驾照号、驾照到期、状态、评分、紧急联系人、备注
- 司机详情：头像、状态、评分、租约总数、已收租金、待收账单、违章记录
- 租约历史、账单记录、违章记录、证件信息、当前状态
- 编辑：认证状态、驾照到期、评分

### 5.8 调度中心

- 统计：待执行调拨、已完成调拨、可调拨车辆、运营门店
- 门店库存矩阵：门店 × 待租/在租/已锁定/维保/调拨中/容量
- 可调拨车辆池：待租车辆、车型、门店、发起调拨
- 调拨任务表：任务号、车辆、调拨路径、计划日期、状态、完成调拨
- 创建调拨：车辆、目标门店、计划日期、备注
- 完成调拨：车辆归属门店更新，状态回到待租

### 5.9 维保保险

- 统计：待处理工单、维修中、30 天内保险到期、已完成维保费用
- 工单标签：全部、保养、维修、年检
- 工单表：工单号、车辆、内容、供应商、计划日期、费用、状态、推进状态
- 状态推进：待排期 → 进行中 → 待验收 → 已完成
- 创建工单：车辆（待租）、类型、计划日期、供应商、预估费用、里程、说明
- 创建后车辆进入维保中；完成或取消后，若无生效租约则释放为待租
- 保险表：车辆、承保公司、保单号、险种、保费、到期日、状态

### 5.10 财务账单

- 统计：待收金额、本月已收、逾期账单、押金池
- 账单标签：全部、租金、押金、违章、车损
- 搜索：账单号、司机、车牌
- 状态筛选、分页
- 账单表：账单号、租约/司机、车辆、类型、金额、到期日、状态、登记收款
- 登记收款：方式、日期、金额
- 生成月租：为生效租约生成下一期租金账单，跳过已存在期间

- 违章记录：车辆、司机、原因、时间、罚款/扣分、状态、处理并生成账单

### 5.11 数据报表

- KPI：平均出租率、已收收入、单车均收、账单逾期率、维保成本

- 车型收入贡献

### 5.12 系统设置

## 6. 核心业务流程

### 6.1 租约全生命周期

```text
创建租约
  → 待签约
  → 签约 → 待交车
  → 交车 → 租用中
  → 办理退租 → 已退租
待签约/待交车 → 取消 → 已取消
```

**创建租约事务**

1. 校验司机存在、状态为已认证/已退租、无生效租约
2. 校验车辆存在、状态为待租
3. 校验门店、日期、金额
4. 创建租约，状态待签约
5. 创建首期租金账单，状态待收
6. 创建租约事件
7. 车辆状态改为已锁定

**签约**

- 待签约 → 待交车
- 记录签约时间
- 写事件

**交车**

- 待交车 → 租用中
- 记录取车里程
- 车辆 → 在租
- 司机 → 租用中
- 写事件

**退租**

- 租用中 → 已退租
- 记录还车里程、关闭时间
- 车辆 → 待租
- 司机 → 已认证
- 有扣款时生成待收车损账单
- 写事件

**取消**

- 待签约/待交车 → 已取消
- 车辆 → 待租
- 写事件

### 6.2 车辆状态机

```text
待租 → 已锁定 → 在租 → 待租
待租 → 维保中 → 待租
待租/在租 → 调拨中 → 待租
任意 → 停运
```

### 6.3 账单状态机

```text
待收 → 已收
待收 → 逾期
待收/逾期 → 免收（数据库支持，界面暂不暴露）
```

### 6.4 维保状态机

```text
待排期 → 进行中 → 待验收 → 已完成
待排期/进行中 → 已取消
```

### 6.5 调拨状态机

```text
待执行 → 在途 → 已完成
待执行/在途 → 已取消（接口预留）
```

### 6.6 违章状态机

```text
待处理 → 已处理
```

处理时尝试关联当前生效租约，生成待收违章账单。

## 7. 数据模型

### 7.1 核心表

| 表 | 用途 | 关键字段 |
|---|---|---|
| `users` | 登录账号（管理员/运营） | name、phone、password_hash、role |
| `stores` | 门店 | name、district、address、capacity、status、image |
| `vehicle_models` | 车型 | slug、brand、name、body_type、range_km、battery_kwh、monthly_rent_cents、hero_image、model_3d_key |
| `vehicles` | 车辆 | plate_no、model_id、store_id、status、mileage_km、insurance_expiry |
| `drivers` | 司机 | name、phone、license_no、license_expiry、status、rating |
| `leases` | 租约 | lease_no、driver_id、vehicle_id、store_id、start_date、end_date、status、monthly_rent_cents |
| `lease_events` | 租约时间线 | lease_id、type、note、created_at |
| `bills` | 账单 | bill_no、lease_id、type、amount_cents、due_date、status、paid_at |
| `maintenance_orders` | 维保工单 | order_no、vehicle_id、type、status、scheduled_at、cost_cents |
| `insurance_policies` | 保单 | vehicle_id、provider、policy_no、end_date、status |
| `violations` | 违章 | vehicle_id、driver_id、reason、fine_cents、points、status |
| `dispatch_tasks` | 调拨任务 | task_no、vehicle_id、from_store_id、to_store_id、status |
| `pricing_plans` | 价格方案 | name、body_type、monthly_rent_cents、deposit_cents、min_term_months |
| `settings` | 键值配置 | key、value |

### 7.2 金额与日期

- 金额：数据库与 API 用整数分，前端统一格式化
- 日期：API 用 RFC3339，前端格式化
- 车辆、司机、租约、账单都有业务编号，便于搜索与展示

### 7.3 种子数据

| 数据 | 数量 |
|---|---|

## 8. 非功能需求

### 8.1 性能

- 首屏不加载 Three.js，只有进入 3D 标签才加载
- 3D GLB 目标小于 2.5MB，懒加载，离开视口暂停
- 图片 WebP、懒加载、首屏主视觉高优先级
- 表格服务端分页，默认 20 条
- 页面切换保持骨架屏，不出现布局跳动

### 8.2 可访问性

- WCAG AA 对比度
- 可见焦点环
- 键盘可达
- 弹窗/抽屉焦点陷阱与 Esc 关闭
- 图标按钮 aria-label
- 跳转到主内容链接
- 尊重 `prefers-reduced-motion`

### 8.3 安全

- 密码 bcrypt
- JWT HttpOnly Cookie，SameSite Lax
- 生产环境 Secure Cookie
- 登录失败统一提示
- 所有业务接口要求登录
- 输入校验与状态机校验
- SQLite 外键开启

### 8.4 兼容性

- Chrome / Edge 最新版
- Safari 17+
- Firefox 最新版
- View Transitions 不支持时降级
- WebGL 不可用时 3D 回退 poster
- 响应式断点：390、768、1024、1440

## 9. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | React 19 + Vite 8 + TypeScript | 组件化、生态成熟、构建快 |
| 样式 | Tailwind CSS v4 | 纯手写 UI，不引组件库，Token 友好 |
| 路由 | React Router 7 | 标准 SPA 路由 |
| 服务端状态 | TanStack Query 5 | 缓存、失效、加载/错误状态 |
| 表单 | React Hook Form + Zod | 登录与复杂表单校验 |
| 图标 | Phosphor Icons | 统一图标族 |
| 3D | Three.js | 颜色切换、相机控制、主题集成 |
| 后端 | Go + Gin | 单二进制、性能好、部署简单 |
| ORM | GORM | 快速建模与关联预加载 |
| 数据库 | SQLite | 零配置、部署简单 |
| 认证 | JWT + bcrypt | 简单可靠 |
| 构建 | Vite + Go embed | 开发双端口，生产单端口 |
