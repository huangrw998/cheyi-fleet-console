# 07 · 样式复用与一致性审计

> 日期：2026-11-25
> 范围：全部页面、公共组件、表单控件、启动脚本
> 目标：优先复用已有组件和样式类；统一间距、圆角、阴影、交互与文案

---

## 1. 审计方法

1. 先扫描现有设计系统：`Card`、`PageHeader`、`CardToolbar`、`FilterBar`、`Tabs`、`Badge`、`Button`、`DataTable`、`Modal`、`ConfirmDialog`、`Toast`。
2. 再扫描 `frontend/src/styles/index.css` 中已有的语义类：`field-control`、`field-control-invalid`、`info-tile`、`info-tile-compact`、`scrollbar-thin`、`hero-scrim`、`skeleton`、`rich-content`。
3. 对比页面实现，优先替换为既有组件；只有确认没有可复用的表面样式时，才新增 CSS 类。
4. 最后用 Playwright 检查页面视觉、交互、移动端与构建结果。

## 4. 交互与文案一致性

- 确认弹窗：租约签约、取消使用 `ConfirmDialog`；表单弹窗统一使用 `Modal`。
- Toast：页面级成功/失败均有反馈；表单内错误保留在表单中，避免重复打扰。
- 加载态：页面使用骨架屏，操作按钮使用 `Button loading`，Modal 底部按钮保持固定。
- 错误态：`Field` 统一错误图标、`role="alert"`、`aria-invalid`；页面级操作失败统一 Toast。
- 按钮文案：页面入口用“新增/发起/新建”，弹窗确认用“创建/保存/确认”，与动作结果一致。
- 页面描述、Toast 描述统一使用完整句号；错误文案从 API 信息回退到“操作失败，请稍后重试”。

## 5. 快速启动脚本

新增根目录 `start.sh` + `scripts/start-helpers.sh`，学习 `oc-session-hub/start.sh` 的结构和文本风格：

- 顶部说明启动端口、模式、环境变量
- 依赖自检
- 编号步骤 `[1/4]` … `[4/4]`
- 启动横幅、访问地址、管理员账号、Ctrl+C 提示
- `cleanup` trap 同时停止前后端
- 默认开发模式；`--prod` 单端口；`--build` 只构建；`--no-open` 跳过打开浏览器
- 检测到已运行服务时直接打开浏览器，避免端口冲突

使用：

```bash
./start.sh
./start.sh --no-open
./start.sh --prod
./start.sh --build
```

## 11. 第三轮一致性复核（2026-11-26）

本轮只复用既有 Token 与组件，没有新增一次性 CSS 类。

| 发现的重复 / 不一致 | 修正 |
|---|---|
| 14 处表单和设置页重复手写危险提示框 | 新增共享 `InlineError`，统一圆角、描边、字号、`role=alert` 与间距 |
| 5 个详情页重复手写返回链接 | 新增共享 `BackLink`，统一 ArrowLeft、字号、hover 与间距 |
| 统计卡片在 StatStrip、司机详情、车辆详情重复手写 hover 容器 | 新增共享 `StatCell`，统一 `p-4`、`hover:bg-card2/50` 与图标强调色 |
| 图表 Tooltip 与富文本链接浮层各自重复写浮层表面 | 统一复用 `.popover-panel`，圆角、阴影和进入动画一致 |
| 14 个 Card 标题缺少统一的 `tracking-tight` | 统一标题字距，与 `SectionHeader`、弹窗标题一致 |
| 设置页门店卡片重复手写卡面 | 改为复用 `Card`，仅覆盖背景与阴影 |
| 总览状态条重复手写 info 表面 | 复用 `.info-tile-compact` |
| 登录页统计标签与接口字段语义不一致 | “在营车辆/认证司机”改为“车队车辆/司机总数”，门店数来自 public overview |
| 部分页面链接、标题、按钮语境不统一 | 详情返回统一 `BackLink`；卡片标题统一 tracking；完成态沿用 disabled 按钮 |

交互一致性结论：

- 页面级加载使用 Skeleton，列表错误使用 ErrorState
- 所有业务写操作统一 Button loading + Toast 成功/失败反馈
- 表单字段错误使用 Field inline error；跨字段/步骤校验使用 warning Toast
- 租约签约、取消等生命周期操作使用 ConfirmDialog；普通单步操作直接执行并反馈
- 完成态操作统一使用 disabled Button，cursor 为 `not-allowed`
